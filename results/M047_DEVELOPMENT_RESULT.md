## Real-software boundary

The mutable body consists of executable source modules for interpretation, planning,
selection, execution, critique, allocation, orchestration and tools. Accepted adaptations
replace source text, add executable tests and may create a new tool module. This is therefore
more than an automaton mutation, configuration-only change or encoding migration.

Candidate source is parsed and bounded before admission. It forbids imports and unsafe
external-system tokens and executes only in disposable isolated worker processes. The
lineage receives no repository, network, credential, deployment or production authority.

## Non-exhaustive proposal boundary

The proposal generator receives the accepted public body, public diagnostic cases, public
execution traces, causal proposal memory and fixed resource limits. It receives neither the
hidden cases nor release authority.

For each diagnosed module it instantiates only a small associated patch family. It does not
enumerate Python programs, source strings, module combinations or the complete candidate
space. Every accepted cycle records a conservative program-space lower bound, generated
patch count, explored fraction and explicit non-enumeration marker.

## Independent validation

A separate task-side validator owns the hidden suite. It requires every baseline and retained
hidden capability, every generated regression test and every current public/hidden case to
pass in a disposable runtime. It also checks that the patch changes exactly the declared
module boundary and respects source and validation budgets.

Only the validator's accepted selection object may enter the transactional lineage store.
The proposal generator cannot adopt its own output.

## Interpretation

M047 is the first Mira Genesis development result in which the continuing mutable organism
is a real modular software application rather than a finite automaton. It can diagnose which
software boundary is limiting a task, write a bounded source/test transformation, submit it
to an independent validator, adopt it transactionally, retain it as a reusable patch/tool and
restore its exact prior state after corruption.

The result remains bounded. The task language, module interfaces, patch templates and hidden
validator are fixed. M047 therefore does not establish arbitrary self-programming,
unrestricted source generation, open-ended evolution, general intelligence, consciousness
or safe production autonomy.

M047 is not canonical. It selected no seed, froze no hidden bank and authorised no canonical
workflow. M042 remains the only positive canonical continuous-lineage completion. The next
construction frontier is a genuine runtime/language migration of this modular lineage with
retained pre-migration capability and new post-migration learning.
