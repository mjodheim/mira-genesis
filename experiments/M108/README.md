# M108 — endogenous modification of the acquisition machinery

**Hypothesis:** H53 · **Decision slot:** D077 (reserved) · **Track:** A — endogenous bounded lineage

M107 changed *what the lineage can express*. M108 asks whether an acquisition can change **how the
lineage performs later acquisitions**.

## The question

The acquisition machinery has to decide, when a capability cannot be built, *which part of itself is
at fault*. M107's machinery could only ever blame the operator table. Faced with a failure caused by
what the lineage is permitted to read, it exhausted the operator candidate space and refused — true
about the operator axis, useless about the failure.

M108 holds the **attribution rule as lineage state**, expressed as a program in the very language the
interpreter runs, over failure features rather than task signals. Acquiring that rule is a
modification of the machinery, not of the vocabulary.

## Why it is a second generation rather than another extension

Every rule consistent with the lineage's own blame record is non-monotone. The complete image of the
monotone fragment over the feature signals holds four programs and none of them is consistent, at
every node bound, by the same monotonicity lemma M107 used.

A lineage that has not acquired a negation-like operator **cannot express its own corrected
attribution rule at all**. Generation 1 is a proved precondition for generation 2. `M0`'s operator
table is not written by hand for this milestone: it is obtained by replaying M107's own frozen
acquisition.

The later capability `B` needs **both** generations — it is outside every liftable image at the base
interface width by complete census, and outside the monotone image at full width by the lemma.
