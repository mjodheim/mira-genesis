# M101 — adversarial pre-implementation review

**Date:** 2026-08-23  
**Scope:** review of `PRE_REGISTRATION.md` before enabling M101 implementation  
**Result:** proceed, with the implementation obligations below treated as load-bearing

This review is deliberately performed while there is still no M101 scientific result to save.

## 1. A could be generic only on paper

A definition can contain no carrier name and still rely on an interpreter branch that implements
special composition separately for text, records and AST.

**Required implementation check:** the combinator execution path must be carrier-neutral over an
opaque value. Carrier-specific code may exist only inside the referenced atomic transformations and
world adapters. The checker must inspect the runtime structure and execute a semantic mutation of A;
a host-side shortcut that keeps the transferred behaviour alive is decisive failure.

## 2. The fresh baseline could be made weaker accidentally

If the retained lineage receives a larger bound, a different validation budget, a more informative
public demand, different atomics, cached producer diagnostics or A's bytes through another field,
transfer is not attributable to retained acquisition.

**Required implementation check:** construct both arms from one canonical baseline descriptor and
diff them. The only permitted causal difference before consumer search is registered A plus the
state digest implied by that registration. The checker must derive and display this diff.

## 3. Transfer could be only a search-cost improvement

A consumer world might be reachable without A if enough one-atomic candidates, repeated host calls or
implicit pipeline execution are allowed.

**Required implementation check:** T0's candidate semantics must contain at most one atomic
transformation. Prove this by closure over the executable candidate representation, not by observing
that a bounded search happened not to find a solution. The more-budget control is secondary to that
proof.

## 4. The producer target is still authored

The experimenter deliberately authors a text demand whose solution class is expected to require
sequential composition. That is not experimenter blindness and must not be described as endogenous
objective choice.

**Required claim wording:** M101 may claim that the *mechanism under test* receives observable demand
rather than an operation label. It may not claim that the scientific objective, carrier families or
need for composition emerged without experimenter design.

## 5. Consumer leakage could make A a disguised lookup

Because the repository is public, excluding consumer data from function arguments is insufficient if
the acquisition process can read the repository or import pool-authoring modules.

**Required implementation check:** A acquisition runs from a minimal isolated capsule with no
consumer pool files, no repository path, no network and no project imports outside the bound capsule.
Record the import census and search paths as scientific evidence.

## 6. A could encode the producer pipeline instead of composition

A shortest accepted program could hard-code the two producer atomics or a text-specific effect while
still satisfying producer cases.

**Required implementation check:** A's symbolic definition accepts transformation references through
slots and contains no concrete atomic IDs or carrier identifiers. The independent validator must
re-derive its generic call semantics with opaque functions not used in the producer world.

## 7. B could be reconstructed rather than persisted

If a fresh T2 consumer still contains the B acquisition/search code, success after producer death does
not prove that B survived as lineage state; it may simply be rebuilt from A and the world demand.

**Required implementation check:** final B-reuse consumers receive serialized state, the frozen
execution runtime and the world only. They must not contain the assembler, acquisition search,
validator or producer demand. A T1-only control with the same consumer runtime but no B registration
must fail the B-reuse worlds or report B absent rather than reconstructing it.

## 8. B could stop depending on A after registration

The producer might expand B to a cached three-stage host pipeline, leaving A historically useful but
not causally live.

**Required implementation check:** stored B must contain content-addressed live references to A.
Digest-valid semantic mutation and ablation of A must break B in fresh consumers. The checker must
reject any stored expanded host expression that eliminates the predecessor reference.

## 9. M100 conservation could be metadata-only

Copying the M100 digest into a new state without preserving executable predecessor semantics would
make the lineage look continuous without actually conserving it.

**Required implementation check:** preserve the exact predecessor state bytes and execute one fresh
world each for M100 subtraction, addition and weighted addition from the final M101 state. A digest
field alone is insufficient.

## 10. The three carrier families could be cosmetic aliases

If text, record and syntax worlds are all encoded as the same internal tuple and differ only by a
label, the result is not materially cross-family.

**Required implementation check:** carriers have genuinely different concrete representations and
atomic catalogs. Record success is measured from exact mapping state; syntax success is measured from
produced Python source/AST and isolated execution where declared; text success is measured from
string values. The shared part is only the acquired higher-order composition semantics.

## 11. Hidden cases could leak through target derivation

The producer and later syntax acquisition must not use qualification-only cases to identify the
needed operation.

**Required implementation check:** the acquisition API accepts a public-case projection type that
cannot contain hidden cases. Independent validation and final qualification may read hidden cases;
search may not. The checker must compare the exact case IDs crossing each boundary.

## 12. Stable replay can repeat M098's mistake

A nested PID or temporary-path aggregate can survive a shallow projection and make replay unstable.

**Required implementation check:** before canonical execution, enumerate the complete result schema
recursively and freeze the exact ephemera projection. A post-verdict projection change is forbidden,
even if the only mismatch is obviously a process identifier.

## 13. A positive 15/15 result still does not close G4

All carrier families, atomics, target-generating fixtures and evaluators are project-authored. The
fresh baseline would establish a real causal transfer comparison, but not independent or natural
cross-domain generality.

**Allowed interpretation after a positive result:** at most `partial bounded cross-family mechanism
evidence` for G4. The existing independent-maintainer and external/private-evaluation requirements
remain open.

## Pre-implementation verdict

No contradiction in the pre-registered question requires changing H46 or the fifteen decisive
conditions. Implementation may proceed only if the final executable protocol binds checks that make
the thirteen risks above falsifiable. If an implementation convenience would weaken one of these
checks, the convenience must be rejected or recorded as a named pre-run amendment before any
canonical qualification.
