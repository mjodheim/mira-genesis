## What moved

Before, `metamorphosis/m090_language.py:run_body` was the authority: it branched on
`MICRO_OPERATIONS` by name, and `_binary` and `_unary` were host functions with hard-coded arms.
Editing that Python changed what the lineage's substrate meant.

Now the authority is a `SubstrateState`: fourteen entries, each carrying a **K1 program** that *is*
the operation's semantics. The host keeps only the K1 kernel, which cannot tell one substrate
operation from another.

| | M091 | M092-A |
|---|---|---|
| micro-operation semantics | host Python arms in `run_body` | K1 programs in serialized state |
| operator semantics (`add`…`max`) | host `_binary` / `_unary` | K1 programs in serialized state |
| dispatch rule | `if name == "PUSH_SLOT"` … | `state.dispatch_key`, read from state |
| legal name set | module constant `MICRO_OPERATIONS` | derived from the registered keys |
| unknown operation | host `LanguageError` | refused; **no fallback path exists** |
| `run_body` | execution authority | **frozen reference oracle only** |

Substrate digest: `ddeb103b64365b93b5c43a6ea83d1b7e7fde22b6efe65dd9e249a3d5820b6e41`
(reported, deliberately **not** sealed).

## State schema

`m092a-state-owned-substrate-v1`. Closed — deserialization rejects both missing and extra fields.

```
SubstrateState:
  operations       : tuple[SubstrateOperation]   # 14 entries
  slot_count       : 4        input_count    : 3
  max_body_length  : 6        max_stack_depth: 8
  literal_values   : (0, 1)
  substrate_version: 0        provenance     : tuple[str]

SubstrateOperation:
  key           : "PUSH_SLOT" | "BINOP:max" | ...   # base name, optional selector
  argument_role : none | index | literal | selector
  program       : tuple[K1 instruction]
  origin        : inherited | acquired              # all 14 are `inherited`
  provenance, capabilities                          # capabilities == ("pure_slot_write",)
```

Dispatch is `key = f"{name}:{argument}"` when `name` is selector-dispatched and `name` otherwise —
and **which names are selector-dispatched is read from the state**, not written in the dispatcher.

## The K1 lower kernel

`m092-k1-lower-kernel-v1`. Eight integer registers, a stack, the slot array, the input array, one
resolved call-time argument. Arbitrary-precision integers; no wraparound, no overflow.

| Group | Instructions |
|---|---|
| control | `HALT` `FAIL` |
| data | `LOADI rd,imm` `MOV rd,rs` `ARG rd` |
| arithmetic | `ADD rd,ra,rb` `SUB rd,ra,rb` `MUL rd,ra,rb` |
| branching | `JMP t` `JZ ra,t` `JNZ ra,t` `JLT ra,rb,t` |
| stack | `SLEN rd` `SPUSH ra` `SPOP rd` `SPEEK rd,ra` |
| memory | `GETSLOT rd,ra` `SETSLOT ra,rb` `GETINPUT rd,ra` |

Jump targets are absolute and bounds-checked at validation. Fuel is
`256 + 4 · max(|inputs|, |argument|)` — a function of operand magnitude only, never of a target value
or a qualifying world. Resource guards: 64 registers-deep kernel stack, 64-instruction programs.

**Contains no** modulo, division, parity operation, target predicate, lookup table, output vector,
qualifying-world constant, experiment-recognizing branch, or host callback. `MOD` and `DIV` are not
in the instruction set, and a test asserts it.

**The kernel branches on no micro-operation identifier.** Checked from the AST with docstrings
stripped: no `PUSH_SLOT`, no `BINOP`, no `"max"` appears in the kernel's executable code. The
scanner is itself checked against a module where those names *should* appear, so it cannot pass
vacuously.

### `can execute` is not `has registered`

K1 can iterate. The registered substrate cannot. Both halves are demonstrated:

- a neutral countdown-accumulator loop runs correctly on the kernel (`sum 1..6 = 21`), and
  `has_backward_jump` reports `True` for it;
- **every one of the fourteen registered programs is loop-free** — zero backward jumps.

A loop-free K1 program is straight-line code with forward branches, which the design audit's K4/K5
rows placed firmly inside the eventual-polynomial invariant. So the registered substrate provably did
not gain reach, whatever the machine underneath it could run.

## Fresh-process authority

The fresh process is allowed the K1 interpreter, the serialized state, and the generic loader and
dispatcher. Two independent mechanisms enforce that: an **import census**, and a **tripwire** that
replaces `run_body` with a function raising on contact.

Import census, printed by the process itself:
`metamorphosis.m090_language`, `metamorphosis.m092_kernel`, `metamorphosis.m092_substrate_state`.
Forbidden modules present: **none** — no migration module, no assembler, no M091 lineage, no fixtures.

| Variant | Result |
|---|---|
| full state | 176/176 probes match, exit 0, census clean |
| **legacy host arithmetic sabotaged** | byte-identical outcomes to the full run |
| state minus `BINOP:max` | 32 probes changed — all became refusals |
| state with `UNOP:neg` corrupted | 24 probes changed semantics |
| state published under a wrong digest | **exit 2, failed closed**, nothing executed |

The sabotage row is the load-bearing one. `_binary`, `_unary` and `MICRO_OPERATIONS` are replaced
with deliberately wrong values before anything runs, and the result does not move. That is what
distinguishes "semantics were copied into state" from "state is the authority".

| Falsifier | Required | Observed |
|---|---|---|
| removing a serialized operation removes the capability | breaks | clamp refuses; unrelated ops unaffected |
| corrupting a program changes semantics | changes | `neg` becomes `+7`, results diverge |
| structurally invalid program at registration | rejected | rejected |
| unknown operation falls through to host semantics | never | refused; oracle still runs it, proving separate paths |
| deleted-but-legal operation recovered from host code | never | refused |
| editing state diverges from the oracle | diverges | `double`→`×3`: oracle 10, state 15 |

**Rollback to the M092-A state** after deliberate damage: bytes identical, digest identical, 2,240

behaviour identical across every declared single-argument binding.

## Proposition M092-I, machine-checked

62 `max` branch-selection certificates over the frozen assembly space, **62 algebraically verified,
0 failed**. Each is re-checked rather than trusted: the difference `p − q` must be identically zero,
or its leading term must provably dominate above the supplied threshold, verified in exact integer
arithmetic via `|a_k| · (T − 1) ≥ max|a_i|` — no floating point, no root-finding, and no reliance on
`sign_threshold`. Sampled sign-constancy is reported separately as corroboration. A certificate with
a falsified threshold is rejected with both findings, so the verifier can fail.

Theorem, certificate and empirical corroboration are kept in separate fields throughout.

## Amendments applied

**Iteration claim narrowed.** The record now says only: *all audited target-neutral non-iterative
extensions preserve the eventual-polynomial invariant; K1 is the smallest audited escape from that
closure.* The stronger "forced by mathematics" form is explicitly marked as not claimed, and as a
defect if it reappears, pending a formal definition of the non-iterative class and a closure proof
for all of it.

**Global correctness made a proof obligation.** Executing a candidate over `0..2999` may not ground a
universal correctness claim. Any positive M092-B acquisition must carry an independently checkable
certificate — precondition/domain, loop invariant, well-founded variant, preservation step,
termination argument, postcondition, and a binding to the exact K1 program digest — re-checked by the
verifier against the actual candidate program, refusing on digest mismatch. Empirical execution is
recorded separately as adversarial corroboration only.

## Weaknesses and failed adversarial attempts

Recorded because they are the parts a reviewer should attack first.

1. **The stack-depth check is dead code on both sides.** A body is at most 6 micro-operations and the
   bound is 8, so `len(stack) > 8` can never fire. It is conserved *vacuously*, and no conservation
   number here should be read as evidence the stack bound was exercised. `stack_bound_is_unreachable`
   records this and a test asserts it.
2. **The fresh process still imports `m090_language`** — for `MetaLanguageState`, `PrimitiveDefinition`
   and `LanguageError`, which are data types, not semantics. `run_body` is tripwired and the sabotage
   variant proves it is not consulted, but the module is loaded. A stricter separation would move the
   state dataclasses out of the module that also defines the legacy interpreter.
3. **One micro-operation name survives in the dispatcher's executable code.** `selector_values('UNOP')`
   appears in the argument-domain check, because the language's `unary_op` parameter kind has to name
   the operation whose selector values are the legal operators. The *domain* still comes from state,
   but the name is hard-coded. A test pins it to exactly this one occurrence.
4. **Refusal comparison is coarse.** Conservation compares *refused vs value*, not exception type or
   message. Two implementations refusing for different reasons would count as agreeing. Check order
   was matched deliberately to reduce this, but it is not eliminated.
5. **Exhaustive only to body length 3.** Lengths 4–6 are randomized, and the adversarial sweep's value
   coverage is modest — 11,818 of 200,000 trials produced a value, the rest refused.
6. **Nothing here tests extension.** M092-A deliberately registers nothing new, so it provides no
   evidence at all about whether endogenous substrate extension is possible. That is M092-B's job and
   is not prejudged.

**Attempts that failed to break it**, tried and reported rather than omitted: 400,000 randomized
bodies at lengths 4–6 including parameterized `$n` operands found no divergence; the germ invariant
was re-checked *through the state-owned path* over 11,712 evaluations with no mismatch; sabotaging
the legacy host arithmetic changed nothing; and deleting or corrupting entries produced exactly the
predicted breakage rather than silent recovery.
