## H50

registry can acquire, independently validate and register a carrier-neutral executable Boolean
classifier F from DEVELOPMENT-only behavior without receiving F's body, identifier, digest or
future consumer material. F must survive producer death and enable later generalized acquisitions

structural/epistemic reason rather than search exhaustion. F must remain a live content-addressed
dependency, all M104 and predecessor capabilities must remain conserved, and corruption plus exact

A positive result would establish **bounded state-owned constructor-vocabulary extension**. It would
not establish endogenous ownership of the lower interpreter, open-ended vocabulary growth,

general-agent evidence or AGI.

## M104 constructive-image closure

Every frozen M104 consumer definition contains a finite closed dispatch from canonical full-context
values to bounded action traces. Its execution domain is exactly the finite set of serialized
contexts in that dispatch: every other context raises before an action runs. Repetition, longer wall
time or a larger feature-subset budget cannot make such a definition invariant to a new opaque nonce
because nonce abstraction is absent from its representation.

M105 later demands declare contexts with two Boolean signals plus an arbitrary opaque nonce. They
require one rule that remains defined when the nonce and previously unseen signal combinations
change. The final apparatus must provide:

1. an independent structural checker of the exact M104 definition schema and execution domain;
2. a symbolic witness that every finite exact-context dispatch omits another valid nonce;
3. a non-materializing execution witness on fresh contexts;
4. a complete census showing that more budget over frozen M104 does not change this image.

If an M104 action, adapter or evaluator can inspect context and perform the missing branch outside
the stored definition, the closure is false and M105 is negative.

## Fixed lower substrate and acquired feature

The initial M105 registry is empty. The authored lower substrate is a closed two-input Boolean
expression language with only:

- constants false and true;
- indexed Boolean inputs 0 and 1;
- unary `NOT`;
- commutative binary `AND` and `OR`.

No `XOR`, equality/inequality, lookup table, target predicate, host callback, carrier operation or
future context literal is permitted. Programs are canonical expression trees of at most eight
nodes. The implementation must compute the complete semantic closure over all four two-bit inputs,
retain a canonical shortest representative for every reachable truth table, and independently show
that all sixteen Boolean functions are represented. This census, not elapsed budget, defines the
feature-acquisition image.

DEVELOPMENT observations label all four signal pairs and include nonce-invariance probes. The
acquisition procedure receives those observations and the generic lower language. It must not
receive an accepted tree, feature identifier/digest, target-operation name, qualification pool,
future carrier action or hidden expected output. It may register F only if exactly one semantic
truth table survives; multiple program trees with that same complete truth table are one semantic
class and the shortest canonical tree is adopted.

The serialized F must contain none of the DEVELOPMENT case/nonce identifiers or values, future
carrier identities, action identifiers, accepted later traces, qualification values or target
digests. Its identifier is content addressed from the complete executable definition.

The lower Boolean vocabulary, eight-node bound, two-signal interface and interpreter remain authored
and become the explicit next ceiling after a positive result.
