# M103 pre-publication review

**Decision date:** 2026-08-24  
**Project owner / research director:** Anthony Mets  
**Disposition:** `PUBLIC_AGPL_COMMERCIAL_OPTION`

This review is recorded before any enabling M103 runtime, constructor-extension mechanism,
qualification population or checker is created. It applies to the successor question derived from
M102 attempt 1 and D071's measured ceiling.

## Asset under review

M103 is intended to test a bounded improvement to the lineage's own future-acquisition machinery.
The exact positive M102 U2 state begins with an inherited constructor S0 whose complete constructive
image contains only context-invariant linear hypotheses. After S0 fails exhaustively on an
observable development demand that requires different transformations in different observable
contexts, the lineage may assemble and register a state-owned constructor extension S-prime from a
generic, bounded feature substrate. S-prime enables the constructor to generate and validate
context-conditioned hypotheses. After the producer process dies, the same serialized S-prime must
make later acquisitions possible in materially different project-authored software carriers while
an otherwise identical S0 lineage remains structurally unable to construct them at any budget.

The materially new public mechanism is the state-owned hypothesis-constructor definition, the
bounded feature-acquisition and validation procedure, the context-conditioned hypothesis grammar,
and the controls that separate constructive reach from search cost. The fixed lower interpreter,
feature vocabulary, demand schemas, action adapters and evaluator remain authored and disclosed.

This is bounded acquisition-machinery improvement evidence if qualified. It is not self-hosting,
unbounded or recursive self-improvement, general-agent evidence, a closure of any generality gate,
or AGI evidence.

## Third-party review

The planned apparatus uses only Python's standard library and the repository's existing development
test tooling. Candidate qualification carriers may exercise `configparser` plus disposable local
filesystem state through `pathlib`/`tempfile`. Those are real Python/operating-system interfaces,
not independently authored task banks, hypotheses, adapters or evaluators. No external package,
model, downloaded dataset, benchmark payload, confidential material, credential, sealed task bank,
network service or remote authority is introduced.

If implementation later introduces another runtime, package, dataset, benchmark or external
payload, this review must be amended before that material enters the public apparatus.

## Scientific-boundary review

M103 must preserve M102 attempt 1, D071 and every predecessor artifact unchanged. It may embed the
exact canonical M102 U2 bytes but may not reconstruct them from qualification observations or edit
M102's protocol, result, checker, digests, tags or verdict.

S-prime acquisition may see development-only observations and the generic feature substrate. It may
not see future configuration/filesystem qualification cases, accepted consumer bodies, target
digests or solution labels. Isolated acquisition processes receive only their declared input bytes
and cannot import the repository. The canonical track remains Track A: zero foundation-model,
network and remote-execution calls. The extension grants no filesystem authority to the lineage;
any disposable filesystem execution remains evaluator-mediated and capability bounded.

M103 must distinguish two causal claims. S-prime must be live and necessary while later hypotheses
are acquired. A compiled later hypothesis may execute without S-prime if that is the real mechanism;
the record must not manufacture a false runtime dependency. S-prime must instead remain necessary
for a still later acquisition after process death. Ambiguous public evidence must cause refusal,
not a greedy tie-break such as the one that invalidated M086-C.

## Decision

Public pre-registration and later project-controlled implementation are authorised under
`PUBLIC_AGPL_COMMERCIAL_OPTION`, subject to an adversarial audit and final executable protocol freeze
before any canonical M103 qualification. A positive result may support only bounded, project-authored
acquisition-machinery improvement with process-persistent causal reuse.
