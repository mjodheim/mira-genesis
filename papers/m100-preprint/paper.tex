\begin{abstract}
Successive benchmark gains in self-improving software do not by themselves establish that an improvement has become reusable system state, survives the process that created it, or causally expands later constructive reach. We present \genesis, a public research program that tests those narrower attribution questions, and report the qualified M094--M100 sequence as a reproducible case study. The sequence begins with measured diagnosis and compositional repair of a repository component, preserves two negative intermediate qualifications and one withdrawn attempt, then establishes bounded acquisition of a new transformation operation, persistence across producer-process death, and repeated cumulative acquisition. M100 uses a fixed stack-based synthesis language in which newly acquired definitions may call only previously registered operations for binary combination. A persisted subtraction operation enables bounded acquisition of addition; registered addition then enables a weighted-addition target within the frozen length-five bound. Building but not registering addition leaves the prior state byte-identical and does not enable the successor. After the final state, the three operations pass 36/36 executions across nine fresh, authored Python-source qualification worlds. Semantic mutation, ablation, state corruption, live fault injection, exact rollback, and stable replay test causal dependence and persistence. The 24 M100 migration, acquisition, control, and execution invocations each run in fresh isolated Python processes inside a two-file frozen capsule; qualification performs zero model, network, or remote-execution calls. The search mechanism itself is standard bounded enumerative program synthesis, and the target family, grammar, bounds, interpreter, and qualification worlds are authored. Accordingly, we claim neither open-ended recursive self-improvement nor cross-domain generality. The contribution is an auditable experimental vocabulary for distinguishing serialized, behaviorally necessary cumulative capability from transient construction, process memory, and externally supplied model competence.
\end{abstract}

\section{Introduction}
Research on self-improving agents has moved rapidly from theoretical self-reference to practical systems that edit their own code, skills, parameters, or agent scaffolds. The G{\"o}del Machine formalized proof-gated self-rewrite \cite{schmidhuber2007godel}; recent systems use foundation models and empirical evaluation to modify agent implementations \cite{yin2024godelagent,robeyns2025selfimproving,zhang2025dgm}. Hyperagents make the meta-level modification procedure editable and report accumulating, transferable meta-level improvements \cite{zhang2026hyperagents}; MetaSkill-Evolve similarly evolves both task skills and the procedure that improves them \cite{wang2026metaskill}. Persistent improvement can also be stored outside source code: Voyager accumulates executable skills \cite{wang2023voyager}, while SEAL uses self-generated update directives to produce persistent weight changes \cite{zweiger2025seal}. AlphaEvolve demonstrates the broader power of evaluator-guided code evolution for scientific and algorithmic discovery \cite{novikov2025alphaevolve}.

These systems motivate a narrower measurement question: \emph{what evidence is sufficient to attribute a later capability to state retained by a continuing software lineage rather than to an external model, the still-live producer process, an evaluator, or an authored host implementation?} A benchmark increase can coexist with hidden dependence on unchanged host code. A serialized record can be behaviorally irrelevant. A later improvement can follow an earlier one chronologically without requiring it. A replay can appear stable while retaining process ephemera.

\genesis studies these distinctions under deliberately constrained, precommitted experiments. The active research line separates an endogenous lineage track, where qualified capability must be attributable to serialized state plus a frozen generic substrate, from a model-mediated governed-agent track, where foundation-model competence remains explicitly attributed to the composed system. The experiments reported here are on the endogenous track. ``Model-free'' in this paper refers only to qualification execution: generative-AI tools were used during project development and manuscript preparation and are disclosed in Section~\ref{sec:repro}.

The main contribution is not a new synthesis algorithm or broad task performance. M097--M100 use finite enumerative search, a standard program-synthesis technique \cite{gulwani2017synthesis}. The contribution is instead an experimentally auditable chain from real-software diagnosis through state-resident capability acquisition, hard process persistence, and bounded causal reuse, with negative outcomes preserved as evidence. The resulting M100 claim is deliberately narrow: \emph{bounded cumulative constructive reach} inside one authored affine family.

\paragraph{Contributions.}
\begin{itemize}
  \item We present an append-only experimental sequence in which M095 and M098 remain negative and an invalidated M094 attempt remains withdrawn rather than being rewritten as success.
  \item We operationalize the difference between a transiently constructed candidate and a registered persistent capability, and test it with a built-but-unregistered control.
  \item We test hard persistence across complete producer-process death and reconstruction in fresh isolated consumers.
  \item We test two successive, bound-relative causal acquisition steps, exact state conservation, later reuse, semantic mutation, ablation, corruption, live fault, rollback, and replay.
  \item We make the authored boundaries explicit and identify cross-family transfer and external reproduction as unresolved next steps.
\end{itemize}

\section{Research discipline and claim boundary}
\genesis is a public repository in which protocols, qualification populations, results, checker outputs, negative results, and provenance records are preserved. Experiments distinguish development evidence from qualified scientific results. Protocols and decision rules are frozen before the evidence they decide is materialized. A failed, invalidated, or withdrawn attempt is retained under its original identity rather than overwritten.

This paper uses the following operational concepts.

\paragraph{Lineage-resident capability.} We use this term operationally, not ontologically: an executable transformation definition is represented in serialized lineage state, is behaviorally consulted after reconstruction, and cannot be silently replaced by a forbidden host implementation under the frozen test boundary.

\paragraph{Constructive reach.} A requirement is in constructive reach when the system can assemble and validate a transformation satisfying the declared executable contract under the frozen operation language and resource bound. Constructive reach is therefore always relative to a grammar and a bound unless a structural impossibility is separately proved.

\paragraph{Cumulative acquisition.} Acquisition is cumulative when an accepted operation is conserved in serialized state and its registration materially changes whether a later target is constructible under the frozen boundary. Mere chronological order is insufficient.

\paragraph{Hard persistence.} Persistence requires termination of the producer process followed by reconstruction and behavioral use in fresh isolated consumers from the allowed serialized state and frozen generic substrate.

The project does not infer general intelligence from these properties. The present paper does not claim experimenter blindness, independent external reproduction, unbounded expressivity, self-hosting, arbitrary self-modification, autonomous objective choice, or production authority.

\section{Mechanism: bounded synthesis with live predecessor calls}
\label{sec:mechanism}
M100 is best understood as a controlled program-synthesis experiment whose purpose is attribution rather than synthesis novelty. The frozen runtime stores a sequence of content-addressed operation definitions. The inherited M097 operation $A$ is subtraction. New M100 definitions may contain only
\begin{center}
\code{PUSH\_LEFT}, \code{PUSH\_RIGHT}, \code{NEG}, \code{SWAP}, and \code{CALL:<prior-id>}.
\end{center}
They may not contain host \code{ADD}, \code{SUB}, or \code{MUL}. Consequently, a newly synthesized definition cannot combine two operands unless it invokes a previously registered binary operation. During execution, a \code{CALL} expands the live referenced definition; no precomputed Python expression or hidden binary host function is stored in the new operation.

For a target affine signature $(a,b)$, the runtime exhaustively enumerates programs up to a frozen length bound, discards malformed stack programs, checks public cases, and requires exact symbolic agreement with $(a,b)$. Candidates are ordered by shortest body and then canonical digest. This is finite enumerative synthesis in a deliberately small DSL \cite{gulwani2017synthesis}; the novelty claim of this paper is not the search procedure.

The accepted definitions themselves retain live calls to predecessors. Schematically, one accepted length-four $B$ body negates an operand and calls $A$, while one accepted length-five $C$ body calls $B$ twice. The checker separately re-derives the affine signatures from the stored token bodies and verifies that predecessor mutations break the dependent operation. The checker is separately implemented but project-authored; ``independent'' below never means an external human replication.

\subsection{M094: measured diagnosis and repair}
M094 anchors the active line in repository software rather than the later synthetic qualification fixtures. The lineage measures structural demand, selects the limiting component rather than receiving the target as a label, and assembles repairs from composable operations. Its preserved second valid attempt passes all twelve protocol conditions and two cross-component qualification requirements. A first positive-looking attempt remains withdrawn because post-verdict audit found that decoded-text equality hid CRLF-to-LF normalization during rollback. The storage mechanism was corrected and a distinct attempt was preserved under the protocol rules. The withdrawn attempt is not counted as positive evidence.

M094 still has strong authored boundaries: the eligible component set, admissible observations, operation set, and composition bound are fixed by the experimenter. It is therefore a real-software diagnosis-and-repair anchor, not an unrestricted repair agent.

\subsection{M095--M096: composition must preserve exact contracts}
M095 asks whether adopting A changes whether B is constructively reachable. Development evidence shows the enabling relation, including a failure-guided descent to a lower-ranked enabler. Qualification nevertheless returns a valid negative: A's locally accepted renderer can emit extra keys, while B requires an exact nested mapping. The six demand-bearing worlds all fail execution confirmation; three negative worlds remain negative.

M096 freezes a distinct successor rather than altering M095. It replaces partial output acceptance with closed exact contracts while leaving the inherited operation language and execution-confirmation structure fixed. The result demonstrates all eight positive relations and preserves all four negative controls, with ten of ten checker conditions true. The pair illustrates why ``operation applicable'' and ``operation composes correctly'' are not equivalent.

\subsection{M097: acquisition of a new operation}
After contract-safe composition, M097 tests the operation-language boundary. Every inherited mapping item reads one \code{self} field, optionally wrapped or rendered; composition does not combine values. The inherited language therefore cannot emit the required binary-expression AST form at any depth. Within a bounded assembly substrate, the system exhausts candidate symbolic programs, validates an accepted definition, registers it in serialized state, and changes Python-source qualification reach from 0/4 inherited worlds to 4/4 extended worlds. The acquired operation is subtraction.

This is not a claim that the entire interpreter is self-authored. The generic interpreter, substrate, and assembly vocabulary remain authored. The qualified change is narrower: a symbolic operation outside the inherited constructive image becomes serialized executable state that later experiments can reconstruct and call.

\subsection{M098--M099: hard process persistence}
M098 introduces a complete process boundary. The producer persists the accepted state and terminates; fresh consumers reconstruct capability from the allowed serialized state and fixed substrate. Direct persistence, controls, and rollback behave as intended, but the stable replay projection accidentally retains an aggregate list of process identifiers. The replay therefore differs and P12 fails: 11/12.

M099 freezes a successor with a complete process-ephemera projection before execution while preserving the causal process mechanism. The acquired M097 operation survives producer death, runs in isolated fresh consumers on three new qualification worlds, fails under absence/mutation/corruption controls, recovers after exact rollback, and stably replays with all twelve conditions true. This closes the specific within-project question of whether the operation survives only in the memory of its producer process; it is not an external reproduction claim.

\section{M100: repeated cumulative acquisition}
\subsection{Frozen question}
M100 asks whether an already persisted acquired operation can become a bounded constructive prerequisite for another acquired operation, which then changes bounded reach for a third, while all earlier definitions remain live and conserved.

The authored affine family is
\begin{align}
A(x,y) &= x-y,\\
B(x,y) &= x+y,\\
C(x,y) &= x+2y,
\end{align}
and the persisted state sequence is
\begin{equation}
S_0 \rightarrow S_1(A) \rightarrow S_2(A,B) \rightarrow S_3(A,B,C).
\end{equation}
The important claim is not arithmetic novelty. It is whether registration changes the bounded constructive language available to subsequent acquisition while preserving live predecessor dependence.

\subsection{Acquisition chain}
At $S_0$, B has zero accepted candidates under bound four. After A is registered, B is acquired with shortest accepted length four: 780 programs are assembled, 28 are well formed, and two satisfy the exact signature. At $S_1$, C has zero accepted candidates under bound five: 3,905 programs are assembled and 90 are well formed, but all disagree with the target behavior. Merely constructing B without registering it leaves $S_1$ byte-identical and C remains absent. After B is registered, C is acquired with shortest accepted length five: 9,330 programs are assembled, 202 are well formed, and six are accepted.

State grows exactly from zero to one to two to three operations. Every $S_1$ definition remains byte-identical in $S_2$, and every $S_2$ definition remains byte-identical in $S_3$. This conservation condition prevents a later state from silently replacing an earlier definition while continuing to use its label.

\subsection{Fresh-world reuse}
After $S_3$, A, B, and C are each exercised on three fresh Python-source qualification worlds with four cases per world. All nine worlds and all 36 cases pass. These worlds are small, authored qualification fixtures with names, field order, arity, scalar types, and narratives varied across entries; they are not sampled production repositories. Their purpose is to test fresh reconstruction and conservation without reusing M097--M099 worlds.

\subsection{Process isolation}
The frozen qualification capsule contains exactly the M100 runtime and a minimal entry point. All 24 migration, acquisition, control, and execution invocations start fresh base-Python processes in isolated mode. The capsule imports no additional \genesis project module and the repository is absent from the interpreter search path. The canonical local run records zero model, network, or remote-execution calls. This boundary does not eliminate authored host semantics: the generic runtime itself is deliberately part of the frozen capsule.

\subsection{Causal controls}
M100 includes controls aimed at causal rather than chronological accumulation:
\begin{itemize}
  \item B is absent without A at bound four; C is absent without registered B at bound five.
  \item Building B without registration leaves $S_1$ unchanged and does not enable C.
  \item A digest-valid semantic mutation breaks B; B digest-valid semantic mutation breaks C.
  \item Removing A or B, and corrupting serialized state, fail closed.
  \item A live digest-valid fault to $S_2$ suppresses C acquisition.
  \item Restoring the exact original $S_2$ bytes reproduces the exact original $S_3$ in a fresh process.
  \item Stable replay changes process identifiers and search paths but no retained scientific field.
\end{itemize}
A separately implemented project checker recomputes all twelve frozen M100 conditions as true, including independent re-derivation of the stored affine signatures.

\section{Why the negative results matter}
The M094--M100 sequence contains two negative qualified outcomes and one withdrawn positive-looking M094 attempt. They are not incidental implementation history.

M095 shows that structural reach can be a misleading proxy for executable composition. The lineage could reach A and make B structurally applicable, while B still failed at execution because acceptance semantics were too weak. M098 shows that a persistence experiment can pass direct behavioral checks while failing stable replay because the evidence projection retained a non-causal field. The M094 withdrawal shows that decoded equality is insufficient evidence for byte-exact rollback.

These failures support a methodological claim rather than a performance claim: evaluation of self-modifying systems benefits from frozen conditions that can invalidate the intended narrative after an apparently successful run. Preserving such outcomes makes the boundary of a positive successor easier to audit.

\section{Relation to synthesis and self-improving agents}
The M100 search itself belongs to bounded enumerative program synthesis: a finite DSL is searched for a program satisfying an executable and symbolic specification \cite{gulwani2017synthesis}. We therefore do not claim synthesis-algorithm novelty. The research question is what must be persisted, reconstructed, and causally required before a synthesized operation is credited as cumulative lineage state.

Persistent skill systems provide an important adjacent comparison. Voyager stores executable code in an ever-growing skill library and reuses those skills in new Minecraft worlds \cite{wang2023voyager}. More recent work explicitly studies evolving skill artifacts: MetaSkill-Evolve recursively modifies task and meta-skills \cite{wang2026metaskill}, while SkillCommit commits behaviorally validated skills and tests cross-instance replay before scope expansion \cite{he2026skillcommit}. SEAL instead makes persistent adaptation directly in model weights through model-generated self-edits and fine-tuning \cite{zweiger2025seal}. These systems operate at much broader semantic scales than M100 and generally rely on foundation-model competence.

Recent self-improving coding agents pursue broader performance objectives. G{\"o}del Agent uses LLM-driven self-reference to modify agent logic under high-level objectives \cite{yin2024godelagent}. A Self-Improving Coding Agent reports substantial benchmark gains after autonomous self-editing \cite{robeyns2025selfimproving}. DGM maintains an archive of self-modified coding agents and empirically validates descendants, producing large SWE-bench and Polyglot improvements \cite{zhang2025dgm}. Hyperagents make the meta-agent itself editable and report accumulation and cross-domain transfer of meta-level improvements \cite{zhang2026hyperagents}. AlphaEvolve uses evaluator-guided evolutionary code generation to improve algorithms and production infrastructure \cite{novikov2025alphaevolve}. A recent survey frames modern self-improvement as self-induced updates to model parameters or scaffold components and highlights evaluation as an open systems problem \cite{ren2026survey}.

\genesis does not claim superiority to these systems. M100 is much narrower in task breadth and semantic complexity. Its complementary emphasis is attribution: qualification execution uses no foundation model; accepted operations must exist in serialized state; producer death is explicit; registration is separated from transient construction; predecessor mutations test downstream dependence; exact rollback and stable replay are part of the qualification; and negative/withdrawn outcomes remain public. The trade is clear: much less capability breadth in exchange for unusually explicit causal and persistence boundaries.

\section{Threats to validity and non-claims}
\label{sec:threats}
\paragraph{Construct validity.} Our term \emph{lineage-resident capability} is an operational definition tied to the frozen state/runtime boundary. It does not imply metaphysical autonomy or a self-authored generic interpreter. The C-on-B dependency is resource-bound: C is absent from $S_1$ at length five, not claimed impossible at arbitrary length.

\paragraph{Internal validity.} Protocol freezing, content digests, fault controls, rollback, and a separately implemented checker reduce some forms of post-hoc reinterpretation, but the experimenter authored the grammar, targets, bounds, worlds, runtime, and checker and was not blinded. The checker is independent in implementation from parts of the measured runtime, not independent in authorship. Generative-AI assistance during development is another source of correlated design error; qualification's zero-model-call boundary does not remove that possibility.

\paragraph{External validity.} M100 contains one affine family, three stored operations, two new cumulative acquisitions, and nine small authored Python-source worlds. It has no cross-family transfer, no sampled production corpus, no cross-operating-system replication reported here, and no independent external human reproduction. Results therefore do not support broad software-engineering competence or open-ended adaptation.

\paragraph{Statistical validity.} The headline M100 counts are deterministic censuses of a frozen finite search space and qualification population, not random samples from a broader task distribution. We therefore report exact counts rather than inferential significance tests; the limitation is coverage, not sampling uncertainty.

\paragraph{Non-claims.} The result does not establish unrestricted self-modification, open-ended recursive self-improvement, arbitrary objective generation, cross-domain transfer, AGI, consciousness, hostile-code containment, or autonomous production authority.

\section{Next experiment: cross-family cumulative transfer}
The next meaningful boundary is not another coefficient within the same affine representation. A stronger successor should derive later transformation needs from materially different observed demands and require acquisition across different operation or representation families. Earlier acquisitions should measurably improve the ability to discover later acquisitions---for example by exposing missing prerequisites, reducing description length or search cost, extending the transformation language, or enabling a representation unavailable at the earlier state.

A useful successor would preserve the M100 controls while changing the source of novelty:
\begin{enumerate}
  \item observe a software insufficiency rather than receive a preselected affine signature;
  \item establish that the inherited language cannot satisfy it under the frozen boundary;
  \item acquire and persist an extension from lineage-resident machinery;
  \item use that extension as a causal prerequisite or discovery aid for a later requirement from a materially different family;
  \item repeat after process death, with conservation, ablation, corruption, rollback, stable replay, and external reproduction if feasible.
\end{enumerate}
Even a positive result would remain below the project's separate generality gates, but it would remove the central authored-family ceiling exposed by M100.

\section{Conclusion}
The M094--M100 sequence provides a bounded, auditable case study in which transformation capability progresses from measured repair to serialized operation acquisition, survives producer-process death, and becomes causally useful to later bounded acquisition. M100 shows that registering prior operations changes constructive reach under frozen resource bounds while conserving and reusing earlier definitions under fresh-process isolation and adversarial controls. The result is not open-ended self-improvement, and the synthesis algorithm is not novel. Its narrower value is methodological: it makes ownership-by-state, process persistence, registration, live dependency, rollback, and replay separately falsifiable. The next test is whether those attribution properties survive materially different transformation families and independent reproduction.
